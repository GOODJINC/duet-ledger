# 운영·업데이트·복구

[매뉴얼 홈](index.md) · [설치](installation.md)

## 평소 운영

Compose 파일이 있는 폴더에서 실행합니다. 다른 위치에서는 `docker compose -f /설치경로/compose.yaml`을 사용합니다.

```bash
docker compose ps
docker compose logs --tail 100 duet-ledger
docker compose restart duet-ledger
```

컨테이너는 재시작 정책에 따라 서버 부팅 후 다시 시작합니다. Docker 자체도 부팅 시 실행되어야 합니다. `/healthz`는 앱 상태 확인용이며 데이터 백업을 대신하지 않습니다.

## 업데이트

먼저 각 기기의 구름 아이콘에서 전송 대기 기록을 동기화하거나 내보냅니다. 이어서 [변경 기록](https://github.com/GOODJINC/duet-ledger/blob/main/CHANGELOG.md)을 읽고 운영 백업과 `master.key`를 별도로 보관합니다. [Releases](https://github.com/GOODJINC/duet-ledger/releases)에서 대상 버전의 이미지 게시 완료를 확인합니다.

Compose와 같은 폴더의 `.env`에서 버전을 지정합니다. 예를 들어 0.3.0으로 업데이트하려면 다음 값을 사용합니다.

```dotenv
DUET_LEDGER_IMAGE=ghcr.io/goodjinc/duet-ledger:0.3.0
```

Docker 관리 화면을 사용한다면 해당 화면의 환경변수 또는 `image` 태그를 바꿉니다. `.env`나 실행 환경에 `DUET_LEDGER_IMAGE`가 있으면 Compose 파일의 기본 이미지보다 우선합니다. 업데이트 시점을 직접 선택하려면 `latest` 대신 정확한 버전을 사용하세요.

```bash
docker compose pull duet-ledger
docker compose up -d
docker compose ps
docker compose logs --tail 100 duet-ledger
```

버전 태그를 고정한 경우 pull만으로 다른 버전으로 바뀌지는 않습니다. 실행 중인 컨테이너는 새 이미지 게시만으로 자동 교체되지 않습니다.

기존 데이터 볼륨·환경변수는 유지합니다. 구조가 자동 변경될 수 있으므로 **이전 이미지로만 바꾸는 것은 안전한 되돌리기가 아닙니다.** 되돌릴 때는 업데이트 전 자료 사본과 호환되는 앱 이미지를 함께 사용하세요.

## 0.3.0으로 업데이트할 때

0.2.0에서 업데이트하면 저장 구조는 **8을 유지**하며 시작 잔액을 다시 전환하지 않습니다. 기존 계정·거래·공유 관계·앱 비밀번호를 유지합니다.

0.1.1 이하에서 바로 업데이트하면 이전 버전의 변경도 함께 적용됩니다. 저장 구조가 8로 갱신되고 기존 시작 잔액은 계좌 생성 시각의 수입(양수)·지출(음수)로 전환됩니다. 현재 잔액은 유지하지만 해당 기간의 수입·지출 통계는 달라집니다. 업데이트 전 백업을 보관하고 변경된 통계를 확인하세요.

업데이트 후 앱을 새로고침해 새 화면을 불러옵니다. 오프라인 저장은 기본 켜짐·최근 7일이며 **설정 → 오프라인 내역**에서 바꿉니다. 공용 기기에서는 끄세요. 화면 갱신 문제를 해결하려고 브라우저의 사이트 데이터를 삭제하기 전에는 대기 기록을 먼저 내보내세요. [오프라인 안내](offline.md)

## 다른 Docker 환경으로 이전

같은 Docker 서버에서는 기존 앱을 중지하고 `duet-ledger-data` 볼륨과 환경변수를 새 스택에 연결합니다. 다른 서버에서는 아래 백업·복원 절차를 사용합니다. **같은 자료를 두 앱에서 동시에 열지 마세요.**

## 백업과 복원

### master.key

`master.key`는 처음 실행할 때 자동 생성되는 서버 비밀키입니다. 현재 2단계 인증(TOTP)의 비밀정보를 암호화하고, 복원할 백업이 원래 키와 맞는지 확인하는 데 사용합니다. 거래 DB 전체를 암호화하는 파일은 아닙니다. **2단계 인증을 사용하지 않아도 운영 백업 복원에는 원래 키가 필요합니다.**

| 설치 방식                 | 키 위치                                                                   |
| ------------------------- | ------------------------------------------------------------------------- |
| 기본 Docker Compose       | 컨테이너 내부 `/data/master.key`. 실제로는 `duet-ledger-data` 볼륨에 저장 |
| 데이터 경로를 변경한 설치 | `DUET_LEDGER_DATA_DIR` 또는 `--data-dir`로 지정한 폴더의 `master.key`     |

Compose 파일이 있는 폴더에 자동으로 생기는 파일은 아닙니다. 같은 데이터 볼륨을 유지하면 컨테이너 업데이트 후에도 키는 유지됩니다. 다른 설치나 개발용 컨테이너의 키는 서로 다르므로 백업을 만든 설치의 원래 키를 사용하세요.

관리자 메뉴 → **백업과 복원 → 키 파일 다운로드**에서 현재 비밀번호와 필요한 경우 인증 코드를 입력해 내려받을 수 있습니다. 키는 서버를 처음 설정할 때 한 번 보관하면 됩니다.

화면에 접속할 수 없다면 기본 컨테이너에서 키를 별도로 복사할 수도 있습니다. 컨테이너 이름을 바꿨다면 명령의 `duet-ledger`도 바꿉니다. 이미 같은 폴더에 키가 있다면 덮어쓰지 말고 설치별 폴더를 따로 사용하세요.

```bash
mkdir -p private-backup
chmod 700 private-backup
docker cp duet-ledger:/data/master.key ./private-backup/master.key
chmod 600 ./private-backup/master.key
```

**키는 운영 백업 ZIP에 포함되지 않습니다.** 백업과 구분해 안전한 장소에 보관하고, ZIP과 어떤 키가 한 쌍인지 표시하세요. GitHub·공개 폴더·메신저에 올리지 마세요. 임의로 삭제·교체하면 기존 2단계 인증을 확인하지 못하거나 정상 복원이 실패할 수 있습니다. 키가 없으면 기존 볼륨과 보관 사본부터 확인하세요. 새 키를 생성해도 예전 키를 대신할 수 없습니다.

### 백업 만들기

1. 관리자 메뉴 → **백업과 복원**을 엽니다.
2. **백업 만들고 다운로드**를 누릅니다. 검증된 ZIP이 서버에 저장되고 장치로 내려받아집니다.
3. 처음이라면 **키 파일 다운로드**도 눌러 `master.key`를 따로 보관합니다.

ZIP에는 모든 사용자의 자료·영수증·공통 디자인이 포함됩니다. **ZIP은 암호화되지 않으며 키 파일은 포함하지 않습니다.** 두 파일을 비공개로 보관하고, 어떤 설치에서 만든 한 쌍인지 표시하세요. JSON·CSV 내보내기는 서버 백업을 대신하지 않습니다.

서버 실행 중 하루마다 자동 백업합니다. 자동 정리 시 수동 생성분과 복원 직전 생성분을 포함한 최근 7개를 남깁니다. **중요한 백업은 다른 장치에도 내려받으세요.**

**복원 전에 각 기기의 전송 대기 기록을 동기화하거나 내보내세요.** 서버 백업에 기기의 대기 자료는 포함되지 않으며, 복원 후 이전 자료 기준의 대기 작업은 자동 반영하지 않습니다. [오프라인 안내](offline.md)

### 화면에서 복원하기

**모든 사용자의 자료가 백업 시점으로 바뀝니다.** 진행 전에 함께 사용하는 사람에게 알리고 다른 작업을 마무리하세요.

1. **백업과 복원 → 복원**을 엽니다. 저장된 백업의 **복원** 버튼으로 시작해도 됩니다.
2. 서버에 저장된 백업을 고르거나 장치의 ZIP을 첨부합니다.
3. 같은 서버에서 만든 백업은 키를 자동으로 확인합니다. 다른 서버에서 만든 백업은 그 백업의 원래 `master.key`를 첨부합니다.
4. **백업 확인하기**를 눌러 백업 시점과 사용자·계좌·거래·영수증 수를 확인합니다.
5. 현재 관리자 비밀번호와 필요한 경우 인증 코드를 입력하고, 자료가 바뀌는 것을 확인한 뒤 **현재 자료 백업 후 복원**을 누릅니다.
6. 백업에 들어 있던 계정 정보로 다시 로그인해 잔액·거래·사진·공유 권한을 확인합니다.

백업 형식·키·DB 무결성·사진을 먼저 검사합니다. 복원 직전에는 현재 자료를 자동 백업하며, DB 반영이 실패하면 기존 자료를 유지합니다. 잘못된 백업을 선택했다면 **복원 직전 자동 백업**으로 표시된 파일을 선택해 같은 절차로 되돌릴 수 있습니다. 이 백업도 보관 정책의 적용을 받으므로 필요하면 내려받으세요.

복원이 끝나면 **모든 로그인 세션·대기 초대·API 앱 비밀번호가 무효화**됩니다. 기존 계정과 승인된 공유 관계는 백업 시점대로 복원됩니다. 웹 복원은 현재 서버의 `master.key`를 유지하며, 다른 서버의 2단계 인증 정보도 현재 키로 다시 보호합니다. 이후 새로 만든 ZIP에는 현재 서버의 키를 사용합니다. 과거 ZIP에는 여전히 당시 키가 필요합니다.

웹 업로드 ZIP은 **512MB**, 압축을 푼 전체 자료는 **10GB**까지 지원합니다. 프록시의 업로드 제한·서버 디스크 여유 공간·전송 시간 제한이 먼저 적용될 수 있습니다. 확인한 백업은 10분 동안 사용할 수 있고, 재시작하면 다시 확인해야 합니다. 실제 백업 검사·생성·복원 중에는 다른 요청이 잠시 대기할 수 있습니다.

### 화면을 사용할 수 없거나 대용량 백업인 경우

서버의 `restore` 명령을 사용합니다. 이 명령은 기존 자료가 있는 폴더를 덮어쓰지 않고 새 폴더에 복원합니다. 아래 절차는 로그인할 수 없거나 별도 볼륨에서 먼저 시험하려는 경우에도 사용할 수 있습니다. `private-backup` 폴더에 ZIP과 원래 키의 복사본을 준비하세요.

### 별도 Docker 볼륨으로 시험 복원

**기존 운영 볼륨은 건드리지 않고 새 볼륨에서 복원합니다.** 아래 `BACKUP.zip`은 실제 파일명, `IMAGE`는 백업과 호환되는 앱 이미지로 바꾸세요. `docker inspect --format '{{.Config.Image}}' duet-ledger`로 확인할 수 있습니다.

```bash
docker volume create duet-ledger-restore-test
docker run --rm --user 0 \
  -v duet-ledger-restore-test:/restore \
  -v "$PWD/private-backup:/backup:ro,Z" \
  --entrypoint sh IMAGE -c \
  '/duet-ledger restore --archive /backup/BACKUP.zip --key-file /backup/master.key --data-dir /restore/restored && chown -R 10001:10001 /restore/restored'
```

`restored` 폴더는 새로 생성되며 이미 자료가 있으면 복원하지 않습니다. 원래 키와 백업이 맞아야 합니다. `:Z`는 SELinux 환경의 폴더 접근을 위한 옵션입니다. 이 폴더에는 복원용 사본만 두세요.

서버 내부에서만 열리는 별도 포트로 확인합니다.

```bash
docker run -d --name duet-ledger-restore-check \
  -p 127.0.0.1:18089:8080 \
  -e DUET_LEDGER_DATA_DIR=/data/restored \
  -v duet-ledger-restore-test:/data IMAGE
```

`http://localhost:18089`에서 다시 로그인해 거래 수·잔액·사진·공유 권한을 확인합니다. 복원하면 기존 로그인 세션·대기 초대·앱 비밀번호는 무효화됩니다. 계정과 기존 공유 관계 자체는 보존되므로 외부 공개 전 확인하세요.

실제 전환 시에는 시험 컨테이너를 중지한 뒤, 본래 `compose.yaml`에서 데이터 볼륨의 `name`을 `duet-ledger-restore-test`, `DUET_LEDGER_DATA_DIR`을 `/data/restored`로 변경하고 기존 서비스를 재생성합니다. **같은 볼륨을 두 서버에서 동시에 열지 마세요.** 이전 볼륨은 검증이 끝날 때까지 보존합니다.

### 로그인 비밀번호 복구

서버 관리 권한이 있고 로그인이 불가능할 때만 사용합니다. 계정 아이디를 확인하고 기존 앱을 중지합니다. 새 비밀번호는 8자 이상이어야 합니다.

```bash
docker compose stop duet-ledger
read -rsp '새 비밀번호: ' duet_new_password
printf '\n'
printf '%s' "$duet_new_password" | docker compose run --rm --no-deps -T \
  duet-ledger reset-password --username 실제아이디
unset duet_new_password
docker compose up -d
```

인증 앱·복구 코드도 잃었다면 `reset-password`에 `--disable-totp`를 추가할 수 있습니다. **이 작업은 해당 계정의 모든 세션과 앱 비밀번호를 폐기합니다.** 복구 후 2단계 인증과 연결 키를 다시 설정하세요.
